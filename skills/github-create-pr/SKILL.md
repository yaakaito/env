# PR を作成する

依頼された変更をレビューできる PR にする。
ユーザーが指定した対象、base、分割方針を優先し、作成した PR の URL を返すまで進める。
下書きだけの依頼では、タイトルと本文を返して完了する。

## 変更の範囲を確かめる

`git status`、現在のブランチ、remote、base との差分と commit 履歴から、PR に入る変更を確認する。
base はユーザーの指定とリポジトリの運用から判断し、ブランチ名を決め打ちしない。
commit 済みの変更は `git diff <base>...HEAD` と `git log <base>..HEAD` で確認する。

未コミットの変更は、会話と差分から依頼に含まれると確認できるものだけを、内容に合った単位で commit する。
PR 作成の依頼を、手元の全変更を取り込む許可として扱わない。
範囲外の変更は保持し、秘密情報を含むファイルは commit しない。
commit メッセージはリポジトリの規約に従い、規約がなければ Conventional Commits を使う。
対象が明確なら、commit や PR 作成の承認を取り直さない。

範囲外の変更が既にブランチに含まれる場合も、そのまま公開せず、元の作業を保持して依頼範囲を分離する。
範囲や base を判断できず、誤った変更を公開するおそれがある場合は、その点だけを確認する。

分割方針が指定済みなら従う。
未指定で、独立した変更を分ける具体的な利点がある場合だけ、各 PR の目的と依存関係を示して分割を提案する。
行数やファイル数だけで確認を必須にしない。
stack が選ばれ、`gh-stack` skill が利用できる場合は、その手順で構築、提出する。

## テンプレートと本文

リポジトリが指定する PR テンプレートを読む。
指定がなければ `.github/`、リポジトリ直下、`docs/` の `PULL_REQUEST_TEMPLATE.md`、`pull_request_template.md`、テンプレートディレクトリを確認し、用途に合うものを選ぶ。
テンプレートがない場合は、概要、主な変更内容、動作確認を含む簡潔な構成にする。

テンプレートのセクションと構造は維持し、不要に見える項目も省略、統合、削除しない。
非該当の欄は、テンプレートに別の指示がなければ空欄にする。
`N/A`、作業ログ、通常のコマンド実行結果で埋めない。

文章の推敲には、利用できる場合は `writing-tech-text` skill を使う。
日本語の場合はその `references/ja.md` も読む。
PR 固有のルールは次のとおり。

- タイトルと本文はユーザーの言語に合わせる。タイトルは目的が伝わる短さにし、リポジトリの規約に従う。
- ユーザーの概要と変更理由を一次資料とし、語彙、文体、時制、確信度を保つ。日本語で文体の指定がなければ常体を使う。
- diff と commit 履歴は事実確認と不足の補完に使う。変更理由を推測で埋めない。必要な判断理由が不明なら最小限の質問をし、回答がなければ分かっている事実だけを書く。
- 概要は問題と変更後の振る舞いを伝える。段落数を固定せず、動機、判断、制約、レビュー上の注意を必要なだけ補う。
- 詳細欄はユーザーの指示やレビュー判断に必要な情報がある場合に埋める。ファイル別の diff 要約、コードから自明な説明、追従しただけの文書やテストの更新は列挙しない。
- 検証結果は、未実施または失敗した検証、通常の CI で扱えない手動確認、変更固有のリスクに対する検証、テンプレートが明示的に求める結果を書く。通常の test、build、lint、help 表示の成功は、明示要求がなければ書かない。
- 関連 issue があればリンクする。

公開前に、本文が最終的な差分を説明していること、ユーザーの文体と確信度を変えていないこと、埋め草がないことを確認する。

## 公開と完了

依頼範囲のブランチを `git push -u` で push する。
本文は実際の改行を含む一時ファイルに保存し、base と head を明示して作成する。

```bash
gh pr create --base <base> --head <branch> --title '<title>' --body-file <body-file>
```

同じブランチの PR が既にある場合や、作成リクエストの応答が不明な場合は、既存 PR を確認して重複作成を避ける。
作成した PR の URL と、必要なら依頼から除外した変更を報告する。

`gh` が使えない場合や API 制限で作成できない場合は、push の成否を確認して次の形式の作成 URL を返す。
owner と repo は remote から取得し、タイトルと本文は改行を含め percent-encode する。

```text
https://github.com/<owner>/<repo>/compare/<base>...<branch>?quick_pull=1&title=<encoded-title>&body=<encoded-body>
```

これは作成済みの PR ではないと明記し、下書きのタイトルと本文、push を含む未完了の操作も伝える。
