# Sync Memory

`MEMORY.md` は repo root に置く git 管理外(`.gitignore` 済み)の判断メモで、この端末専用。過去の sync でユーザーが確定した判断を記録し、同じことを二度確認しないために使う。

## Template

`MEMORY.md` が存在しないときは、このテンプレートで作成する。

```markdown
# Sync Memory

dotfiles-skill-sync が過去の同期で確定した判断の記録。git 管理外で、この端末専用。

- 1 判断 = 1 行。行を削除すると、その対象は次回の sync で再び確認される
- 秘密情報の値そのものは書かない。キー名、パス、種類だけを書く
- `内容の要点` は再確認の要否を判断する材料。実際の差分がここから変わっていたら、記録があっても再確認する

| 対象 | 分類 | 内容の要点 | 理由 | 記録日 |
| ---- | ---- | ---------- | ---- | ------ |
```

## What to record

記録するのは「放っておくと次回また確認になる、ユーザーが確定した判断」だけ。

| 記録する | 例 |
| -------- | -- |
| Local keep と確定した差分 | `~/.gitconfig` の `[user]` セクション |
| 削除候補に挙げたがユーザーが残すと決めたもの | 手動運用中の zsh helper |
| Merge needed の解消方針(次回も同じ差分が出るもの) | repo 版を基準に local の追記だけ残す、など |

記録しないもの:

- Repository update として repo に取り込んだ変更。差分自体が消えるので記録不要
- ユーザーがまだ判断していない、こちらの推測にすぎない分類
- 秘密情報の値そのもの。対象のキー名・パス・種類だけを書く

## How to read

sync の分類が終わったら、各差分を `MEMORY.md` の `対象` と突き合わせる。

- 記録があり、実際の差分が `内容の要点` と一致している: 再確認せず記録どおりに扱う。計画では「記録済み」と明示する
- 記録はあるが差分の内容が変わっている: 再確認する。確定したら行を更新する
- 記録がない: 通常どおり確認する

## How to write

- 1 判断 = 1 行で追記する。同じ `対象` の行が既にあれば、行を増やさず更新する
- `対象` は端末側パス + 必要ならセクションや行の識別子(例: `~/.gitconfig [user]`)。ユーザーが後から見て特定できる粒度にする
- `分類` は SKILL.md の分類語彙(Local keep など)か「削除見送り」を使う
- `記録日` は更新のたびに当日に付け替える

## Maintenance

ユーザーが手で編集して管理する前提のファイルなので、構造を複雑にしない。

- 特定の判断を取り消したいとき: 該当行を削除する。次回の sync で再確認される
- 全部やり直したいとき: 表の行を全部消すか、ファイルごと削除する(次回の sync でテンプレートから再作成される)
- `対象` が端末から消えた・`setup.yaml` から外れたことに sync 中に気づいたら、行の削除を提案する
